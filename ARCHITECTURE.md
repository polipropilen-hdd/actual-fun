# Конструктор интерактивных упражнений — архитектура

**стек:** vanilla JS (ES modules), без фреймворков, без сборщика, без внешних зависимостей.
**модель распространения:** статический сайт → GitHub Pages. Бэкенда нет: вместо API — формат JSON + инструкция для нейросетей.

---

## 1. Слои и каталоги

```
constructor/            конструктор (то, что лежит в корне GH Pages)
  index.html            оболочка UI
  styles/               CSS конструктора
  js/
    core/               модель документа, состояние, валидация, сериализация
      document.js       ExerciseDocument: создание, блоки, метаданные, лимиты
      state.js          единое состояние + подписки (pub/sub), автосейв в localStorage
      validate.js       структурная валидация, сообщения об ошибках (RU)
    types/              РЕЕСТР ТИПОВ — по одному файлу на тип упражнения
      registry.js       addType(), getType(id), listTypes()
      drag-word.js      схема + дефолты + нормализация + описание для формы
      drag-parts.js
      match-columns.js
      choice-single.js
      choice-multi.js
      reading.js
    form/               общий генератор форм из схемы типа
      schema.js         DSL схем: text, textarea, number, list, group, select
      render.js         renderer: схема -> DOM-формы (field, repeatable list, add/remove/move)
    preview/            рендер предпросмотра внутри конструктора (iframe, тот же рантайм)
    export/
      template.html     каркас итого файла с маркерами {{STYLES}} {{RUNTIME}} {{DATA}}
      build.js          подстановка: стили игрока + код рантайма + JSON данных
      bundle.js         получает тексты модулей рантайма и собирает один HTML
  data/                 примеры документов (*.json) для загрузки
runtime/                плеер упражнений (используется и в предпросмотре, и в экспорте)
  player.js             загрузка документа, навигация по блокам, проверка, итог, рестарт
  scoring.js            подсчёт баллов по типам
  ui-styles.css         стили игрока (инлайнятся в экспорт)
  interactions/         по файлу на тип: drag-word.js, match-columns.js, ...
schema/
  exercise.schema.json  JSON Schema документа (для проверки нейросетями и людьми)
docs/
  NEURAL_API.md         инструкция для LLM: как составить JSON, все типы, примеры
  ADDING_TYPES.md       как добавить новый тип упражнения (3 шага)
```

**Ключевое правило импортов:** `types/*` и `runtime/interactions/*` зависят только от `core`. Ядро не знает ни об одном конкретном типе. Всё знание о типах — в реестре.

## 2. Модель данных (ExerciseDocument)

```jsonc
{
  "format": "lingua-exercise/1",   // фиксированная строка: маркер формата
  "version": 1,                     // версия схемы, для обратной совместимости
  "meta": {
    "title": "Упражнения: Падежи",  // обязателю нет, но используется в <title> и шапке
    "language": "ru",               // язык интерфейса игрока (пока всегда ru)
    "description": "",
    "author": ""
  },
  "settings": {
    "showResultScreen": true,       // экран итога
    "shuffleBlocks": false,         // перемешивать порядок блоков
    "theme": "light"                // light | dark
  },
  "blocks": [ /* 1..20 элементов */ ]
}
```

Блок:

```jsonc
{
  "id": "b1",                       // уникален внутри документа; при загрузе генерируется, если отсутствует
  "type": "drag-word",              // ключ из реестра типов
  "title": "Расставьте слова",      // заголовок блока (необязательно)
  "instruction": "Перетащите слова в пропуски.",  // подсказка ученику (необязательно)
  "data": { /* специфично для типа, см. §4 */ }
}
```

Правила:
- Максимум **20 блоков** на экспорт — проверяется при загрузке JSON и при добавлении блока в UI.
- `reading` — обычный блок, ничем не связан с другими: «связки» делаются просто порядком блоков (текст → упражнение по нему). Никаких внешних ключей между блоками.
- Порядок блоков = порядок показа в игроке (если `shuffleBlocks` — перемешивается только показ, данные не меняются).

## 3. Контракт типа упражнения (модульность)

Каждый файл в `types/` экспортирует один объект-дескриптор и регистрируется в `registry`:

```js
export default {
  id: 'drag-word',                 // уникальный ключ, совпадает с block.type
  name: 'Слова в пропуски',         // подпись в палитре типов (RU)
  icon: '🅰️',
  defaults: () => ({ /* пустой data для нового блока */ }),
  schema: [ /* форма-описание, см. ниже */ ],
  normalize(data) { /* привести загруженный JSON к канону: числа, массивы, trim */ },
  validate(data) { /* [] ошибок вида {path, message} — только содержательные проверки */ },
  isComplete(data) { /* true, если блок можно экспортировать */ }
}
```

Рантайм-часть (для игрока) — отдельный модуль `runtime/interactions/<id>.js`:

```js
export default {
  id: 'drag-word',
  mount(container, block, ctx) {
    // ctx: { check(), award(score), setRevealed(bool), getState(), setState(s) }
    return { scoreMax: n }   // сколько баллов даёт блок
  }
}
```

**Добавление нового типа (3 шага, ядро не трогаем):**
1. Создать `types/<id>.js` (схема + дефолты + валидация).
2. Создать `runtime/interactions/<id>.js` (рендер и логика в игроке).
3. Добавить два `import` в `registry.js` и `runtime/player.js`.
Формы в конструкторе появятся сами — они генерируются из `schema`.

DSL схем (типы полей): `text`, `textarea`, `number`, `checkbox`, `select{options}`, `group{fields}`, `list{item:[fields]}` (повторяемый список с кнопками «+», удалить, вверх/вниз). Это позволяет не писать форму на каждый тип вручную.

## 4. Данные по шести типам

### 4.1 `drag-word` — слово в пропуск
```jsonc
"data": {
  "items": [
    {
      "sentence": "Я читаю ___ каждый день.",   // ровно один пропуск на item, маркер ___
      "answer": "книгу",                        // должен встречаться среди words
      "words": ["книгу", "стол", "окно"]         // дистракторы включены; перемешиваются игроком
    }
  ]
}
```
Взаимодействие: тап по слову → тап по пропуску (и обратный тап для возврата). Drag-and-drop мышью — как дополнительный способ.
Оценка: 1 балл за item при полном совпадении всех его пропусков.

### 4.2 `drag-parts` — части предложения
```jsonc
"data": {
  "items": [
    {
      "parts": ["Вчера", "я", "шёл", "в кино"],  // верный порядок слева направо
      "translation": null                          // необязательно, подпись под строкой
    }
  ]
}
```
Ученик выкладывает части в линию из перемешанного набора. Оценка: 1 балл за item, если порядок полностью верен (частичных баллов нет — иначе усложнение контракта).

### 4.3 `match-columns` — две колонки
```jsonc
"data": {
  "pairs": [
    { "left": "house", "right": "дом" },
    { "left": "window", "right": "окно" }
  ]
}
```
Левая колонка в заданном порядке, правая перемешивается. Соединение: тап по левой → тап по правой (мышь: те же клики, линии рисуются SVG). Удалить связь — тап по связи.
Оценка: 1 балл за пару.

### 4.4 `choice-single` — один вариант
```jsonc
"data": {
  "question": "Выберите правильный перевод.",
  "options": ["дом", "окно", "стол"],
  "correct": 0                    // индекс; при загрузе валидируется диапазон
}
```
Оценка: 1 балл за вопрос.

### 4.5 `choice-multi` — несколько вариантов
```jsonc
"data": {
  "question": "Отметьте все глаголы.",
  "options": ["читать", "стол", "писать", "красный"],
  "correct": [0, 2],              // индексы; >=1 обязательно
  "scoring": "exact"              // exact | partial (по умолчанию exact)
}
```
`exact`: балл только при точном совпадении множества. `partial`: `max(0, верно_отмечено - ошибочно_отмечено) / len(correct)`, округление до 0.01.

### 4.6 `reading` — текст для чтения
```jsonc
"data": {
  "heading": "Мой день",
  "paragraphs": ["Утром я встаю...", "Потом я иду..."]   // markdown не поддерживается, только абзацы
}
```
Без проверки: `scoreMax = 0`, учитывается как выполненный при открытии. Экран итога показывает процент только по оцениваемым блокам.

## 5. Формат и загрузка JSON (вместо API)

`docs/NEURAL_API.md` — это и есть «API для нейросетей»: человек копирует туда свой запрос вместе с инструкцией, LLM возвращает JSON, пользователь загружает файл в конструктор.

Что должно быть в инструкции:
- полный список полей документа и каждого типа (как в §2, §4);
- JSON Schema (`schema/exercise.schema.json`) для автоматической проверки;
- правила: максимум 20 блоков; `___` только один на item в `drag-word`; `correct` — индексы, а не значения; поля на русском могут содержать любой текст;
- разборчивость: неизвестный `type` или лишние поля → не ошибка, а предупреждение;
- 2 полных примера (один маленький, один со связкой «чтение + задания»).

Обработка загрузки в конструкторе (`core/validate.js`):
1. Парсинг; отсутствие `format === "lingua-exercise/1"` → отказ с понятным сообщением.
2. Проверка структуры по схеме, затем `normalize()` и `validate()` каждого типа.
3. Ошибки выводятся списком в RU: `Блок 3 (drag-word): answer «книга» нет в списке words`.
4. **Загрузка ≠ экспорт.** Документ попадает в обычное редактируемое состояние: можно менять всё, добавлять/удалять блоки, потом экспортировать. Загруженные ошибки не блокируют редактирование — блокируют только кнопку «Экспорт».
5. Совместимость: неизвестный `type` сохраняется как есть (данные не теряются), блок помечается «неизвестный тип», в игроке пропускается.

Сохранение проекта — тот же JSON (`Скачать проект` / `Загрузить проект`), плюс автосейв в `localStorage`.

## 6. Экспорт в один HTML

Экспортируемый файл полностью автономен: открывается с телефона по `file://`, работает офлайн, никаких запросов наружу.

Как собирается без сборщика:
- `export/bundle.js` fetch'ит тексты своих собственных модулей (`runtime/*.js`, `runtime/interactions/*.js`, `runtime/ui-styles.css`, `export/template.html`) через `fetch` — они лежат рядом на том же хостинге;
- оборачивает каждый модуль в IIFE и склеивает в один `<script>` (ES-модули внутри файла запрещены браузерными политиками `file://`, поэтому именно склейка);
- результат: `<!doctype html><html lang="ru">…{{STYLES}}…{{RUNTIME_JS}}…<script>window.__EXERCISE_DATA__ = {...}</script>…player boot…</html>`;
- данные вставляются как JSON c экранированием `<`, `>`, `&`, U+2028/2029, чтобы не сломать инлайн-скрипт.

Размер: ~25–40 КБ gzip, один файл.

Ограничение GH Pages: `fetch` своих файлов не работает при локальном открытии `constructor/index.html` с диска. Поэтому в README — обязательный запуск через `python3 -m http.server` (или `npx serve`). На Pages всё работает из коробки.

## 7. Поведение игрока (согласно решениям)

- В каждом оцениваемом блоке — своя кнопка **«Проверить»**: подсветка правильных/неправильных позиций, счётчик баллов блока.
- Кнопка **«Показать ответ»** — отдельная, разблокируется после проверки; показывает эталонное заполнение.
- Кнопка **«Начать заново»** сбрасывает весь документ (состояние и прогресс), подтверждение.
- Навигация: список блоков сверху (прокрутка к блоку) + кнопки «назад/вперёд»; на узких экранах — одна колонка.
- **Экран итога** внизу и по кнопке «Итоги»: набрано X из Y (Z %), разбивка по блокам, статус «есть незаполненные».
- Прогресс не сохраняется между сессиями (нет localStorage в игроке) — всегда с нуля.

## 8. GitHub Pages

Работает без изменений: статические файлы, никаких серверных обработчиков.
- Деплой: `Settings → Pages → Deploy from a branch → / (root)`; либо GitHub Action с `actions/deploy-pages` (при необходимости поддомена).
- Репозиторий плоский: корень = конструктор; `runtime/`, `schema/`, `docs/`, `examples/` — подпапки того же сайта.
- Единственное требование к путям — относительные (`./runtime/player.js`), чтобы работало и на `https://user.github.io/repo/`, и в сабмодулях.

## 9. Этапы реализации

1. **Каркас**: `index.html`, роутинг состояния, `core/document.js`, `registry.js`, пустые формы.
2. **DSL схем + form-renderer** (общий генератор форм) — самый высокий риск, делаем рано.
3. **Три простых типа**: `reading`, `choice-single`, `choice-multi` (без drag) end-to-end: форма → данные → предпросмотр.
4. **Рантайм + экспорт**: `template.html`, `bundle.js`, игрок, проверка/итог/рестарт. Проверяем на телефоне.
5. **Три drag-типа**: `drag-word`, `drag-parts`, `match-columns` (тап-в-тап как основной способ).
6. **Загрузка JSON**: парсер, валидатор, сообщения об ошибках, merge в состояние.
7. **Docs**: `NEURAL_API.md`, `exercise.schema.json`, примеры, README (GH Pages + локальный запуск).
8. **ADDING_TYPES.md** + ручной тест: добавить 7-й тип («раскрытие скобок») за один присест, чтобы подтвердить модульность.
